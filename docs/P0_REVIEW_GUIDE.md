# P0 审阅路线 · 2026-10-16

建议先打开审阅站的“首屏线框”，按以下路线检查。当前交付只覆盖资料、构图、文字、导航与范围；静态图不作为真实三维拆解或性能证据。

## 1. 首屏：10 秒内能否看懂目的

主标题为“一步棋，背后的机器。”说明用一句话连接人的知识、搜索与并行硬件。模型线框占主要区域，暖纸色引导卡提供一个主要动作。机柜、引导卡与主要操作都有明确边框；蓝色表达选择，琥珀色表达当前任务。

你要检查：首次看到页面，是否知道这里研究什么、下一步点什么。点“展开可能性”，会进入下一张静态教学构图；顶部“集群 / 节点 / 芯片”可以直接看三层。底部五步可来回切换，解释使用折叠项。

手机线框以可读性为先，按模型、当前指引与操作顺序纵向安排。最终产品的一屏与自适应构图在 P1/P5 继续验证，不能以 P0 静态审阅页代替最终验收。

## 2. 六个镜头是否连续

| 镜头 | 观察对象 | 动作与关系 | 进入 P1 后的检查 |
| --- | --- | --- | --- |
| F01 | 双柜与棋桌 | 整体先交代体量和问题 | 道具不会侵占门板通道 |
| F02 | 小型搜索树 | 双方交替选择，逐步引出剪枝 | 教学界面不冒充历史日志 |
| F03 | 柜门与节点 | 门先让位，再接近节点 | 门板扫掠范围与抽出轨迹分开 |
| F04 | 节点 | 先脱开连接、完整抽出，再移外盖 | CPU、两卡和外盖之间有独立空间 |
| F05 | 一块加速卡 | 沿安装方向离开，再调整观察角度 | 离开连接器以后才旋转 |
| F06 | 一颗芯片 | 切到放大教学剖面，再回整机 | 放大与功能示意标签始终可见 |

P0 只定义运动依赖与检查条件。P1 才依据包围盒、中间姿态和实际镜头验证不穿插。

## 3. 本轮锁定与保留的区别

已锁定的逻辑配置：1997 比赛搜索系统使用 30 节点、每节点一个 P2SC、两卡各 8 象棋芯片，总计 480 芯片。来源与出版口径差异记录在史实表。

外观以馆藏双塔照片为主，保留黑色网孔门与顶部编号。蓝色作为界面重点色使用；专用蓝带和大铭牌缺少对应照片，暂不列为实物细节。

芯片采用功能教学层：着法生成、评估、搜索控制、走法栈与重复检测。置换表在软件层；功能区颜色不代表实际版图边界。

保持待核的项目：机柜实测尺寸、侧面和开门结构、PCB 与器件排布、封装和丝印、棋盘品牌及精确功耗。P1 可使用带“教学重建”标签的统一比例模型；P4 精化前再次审查相关资料。

## 4. 需要你判断的五件事

1. **D01 视觉方向**：工业档案馆、炭黑机柜、暖纸色说明是否合适？
2. **D02 教学顺序**：棋局 → 搜索 → 剪枝 → 节点 → 芯片是否足够直白？
3. **D03 外壳选择**：采用有出处的轮廓与编号，能否满足你要的历史感？
4. **D04 重建边界**：配置准确、未证实的机械细节明确标注，这个范围是否可接受？
5. **D05 道具范围**：棋桌和 CRT 保留，精确品牌与戏剧化小道具延后，是否聚焦？

站点“范围与审阅”页提供逐项意见和导出功能；也可以直接在聊天中按 D01–D05 指出修改。所有判断默认待审阅。技术检查完成与用户认可方向分别记录。

## 5. 下一阶段的入口条件

P0 资料可查、参考图与示意边界清楚、六镜头顺序完整、线框可以操作之后，等待用户审阅。获得进入 P1 的指令后，先做低精度双柜和完整拆解路径，再依据实际运动决定柜内间距与相机。

P1 不以昂贵纹理或道具堆砌代替几何检查。后续沿用现有的 Three.js 技术方向，并保持页面控件、状态、模型与算法分离。
