# Deep Blue P1 · 可操作低精度三维模型设计

日期：2026-10-17。状态：待用户审阅；尚未实施。

## 1. 意图与范围

用户确认按现有 P0 方向继续 P1。面向非专业观众，用可操作的空间关系解释“双柜集群 → 单节点 → 加速卡 → 芯片”，重点是进入、拆解、返回和复位，而不是精美材质或搜索算法演示。

沿用工业档案馆视觉：炭黑机柜、暖纸展签、蓝色选择态。保留 P0 全部资料和审阅入口；不把本次继续指令写成 D01–D05 逐项通过。模型始终标明“教学重建，非实测尺寸”；芯片视图标明“放大功能示意，非实际版图”。

## 2. 方案选择

采用 Three.js 程序化低模 + 原生 DOM 控件 + esbuild 本地打包。理由是现有技术方向一致、无外部模型依赖、易于从原始姿态计算运动，并能单独测试几何和状态。

备选一：离线 Blender/GLB。适合后续材质精化，但本阶段会增加资产管线和运动排查成本，不采用。

备选二：继续 SVG/CSS 伪三维。成本低，但无法可靠检查真实空间关系，不满足 P1 目标。

## 3. 入口与模块边界

保留 4175 端口及现有 P0 根入口，在审阅页加入“三维原型”链接；P1 使用独立 /prototype/ 入口与独立源文件，不把三维渲染逻辑塞入 review.js。构建同时保留 P0 文档生成和打包 P1；浏览器无需外部 CDN。

- model：由 MODEL_CONTRACT 的配置构造双柜、节点、盖板、两张卡及每卡八颗芯片；暴露可动对象引用和初始姿态。
- motion：纯数据运动分段、姿态求值、几何检查；不依赖 DOM 或渲染循环。
- state：负责目标步骤、连续进度、前进/后退/复位和 reduced-motion；单一状态驱动模型、镜头、说明。
- scene：相机、光照、渲染、轨道观察、尺寸更新、选择拾取与资源释放。
- main/UI：按钮、键盘、说明和错误提示，只发出意图、不直接改模型坐标。

使用一个 requestAnimationFrame 循环；页面不可见时暂停时间推进，恢复时不累计长时间跳跃。WebGL 不可用时显示原因和返回 P0 的链接，不显示假三维成功状态。

## 4. 配置和历史边界

配置沿用 2 柜、30 个搜索节点、每节点 1 个 P2SC、2 卡、每卡 8 芯片，逻辑总数 480。教学布局暂用每柜 15 节点，不声称对应历史槽位映射。只精化一个选中节点，其余节点为低模实例；选中节点必须从柜内原位抽出，不能以额外复制件冒充同一对象。

显示单位和轴向沿用 MODEL_CONTRACT：+Y 向上、+Z 向前、+X 向右。尺寸不足以容纳器件时调整示意比例，明确记录变更，不将草图尺寸当成实测约束。P1 不增加未经证实的丝印、机械锁扣或线缆服务步骤。

## 5. 运动与导航

四个观察站点：整机、节点、板卡、芯片。前后切换遵守下列可逆分段，不跳过前置动作：

1. 柜门绕 Y 铰链向外让位；选中节点抽出通道保持畅通。
2. 用说明和连接状态表达教学性断开，不动画拉伸连接中的线缆。
3. 节点沿 +Z 完全离柜。
4. 外盖先向 +Y 抬升，再移向空闲侧。
5. 选中卡沿插拔轴离开连接器，完全脱离后才允许转向展示；第二张卡保留可见。
6. 切入独立放大芯片教学层，隐藏容易混淆尺度的整机场景，保留返回路径；不表现成真实芯片拆封。

所有姿态由初始姿态和绝对进度求值，不逐帧累加坐标。快速点击以最新目标为准，允许从当前进度反向返回，不排队旧动作。复位回到规范初态与初始相机。启用减少动态效果时直接到达同一终点。自由观察后的站点切换会重新聚焦，界面明确提示。

提供上一步、下一步、整机复位、四站点选择和正/侧/顶观察。用真实 button 支持键盘；状态说明使用克制的 aria-live。手机端画布与说明纵向排列，避免控件覆盖关键模型。

## 6. 验收与证据

自动化使用 Node 内置测试运行器，先写会失败的行为测试，再实现运动/状态：

- 配置数量一致；节点内 1 CPU、2 卡、16 芯片，系统逻辑总量 480。
- 门未清空通道时节点不抽出；节点未离柜时盖板不抬起；卡未脱离时不旋转。
- 用变换后的包围盒对预先指定的实体对采样整个运动；检查门与节点通道、盖板与 PCB、两卡之间的间隔。铰链和连接器接触区域单独定义允许边界，不能用全局忽略碰撞。
- 任意中途反向、连续切换、重复往返与复位后，姿态回到原值（浮点容差 1e-6）。
- reduced-motion 与普通模式的最终模型、相机目标和文字一致。

浏览器检查桌面与窄屏：完整进入/退出；快速往返；中途复位；键盘；三种观察方向；WebGL 失败提示；P0 入口不退化。各运动起点、中间、终点保留正/侧/顶观察证据；数值包围盒检查仅作为视觉检查的补充，不单独宣称不穿插。

build、既有 validate、新增 test 均通过后记录结果。帧率以实际设备为准，本阶段不承诺未测量的 60fps 或手机性能。
